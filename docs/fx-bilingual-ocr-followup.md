# FX 双语硬字幕 OCR：复现与处理

复现素材为 `/Users/portz/Downloads/fx-01.mp4`；独立命令 `tenmin ocr` 的原始输出在 `work/fx/srt/fx-01.zh-Hant.srt`，简体输出在同目录的 `fx-01.zh-Hans.srt`。这两份工作区素材不作为仓库 fixture。

## 已确认的现象和原因

- 约 17:19（cue 284）中文后混入 `老取3の`、`特尼叨 夕`；约 17:52（cue 292–293）同一中文字幕被拆成两条，部分帧还混入 `勝 逃埗`。`--traditional` 的原始 OCR 输出也有这些问题，因此不是繁转简造成的。
- 画面上方是粉色中文，下方是青色日文。现有 `crop_top=.72` 从 1080p 视频的 y=778 一直裁到画面底部，两种字幕都进入 Apple Vision；`center_tolerance` 只筛水平方向，不能排除同样居中的日文。实测裁剪后归一化坐标：中文约 y=.15–.21，日文约 y=.03–.05（Vision 坐标自下而上）。仅靠“含 CJK”无法区分含汉字的日文。
- `frame_text` 按 y 排序；同一行中文字幕被分成多个 OCR 框且 y 略有抖动时，左右顺序跨帧翻转。`merge_frames` 据此把近似相同的内容拆成相邻两条 cue。

## 已实施的处理

1. 新增可选 `OcrConfig.crop_bottom` / `tenmin ocr --crop-bottom`，按**原视频高度比例**指定字幕带下沿；取帧仍沿用 `crop_top` 一直裁到画面底部，在 Vision 识别后用文字框**中心**过滤下层日文。首次实验用 ffmpeg 物理裁掉下层：虽清除了 17:19 与 17:52 的日文，但使靠近裁剪边缘的真中文 `从FX中脱身` 漏认；因此改成识别后过滤。默认 `None` 不启用纵向过滤。
2. `frame_text` 将相近 y 的文字框视作同一行，同一行按 x 从左到右、各行按 y 从上到下拼接；这样 17:52 被拆框的 `就是说 赚了就跑` 跨帧顺序一致。
3. FX 实测命令：`uv run tenmin ocr /Users/portz/Downloads/fx-01.mp4 -o work/fx/srt --crop-bottom 0.95 --force`（可加 `--traditional` 保留原文）。全片 17:19 的下层日文不再混入，17:49 的中文保留，17:52 的重复 cue 合并。独立命令不读取 `work/fx/project.yaml`；走管线时须在其 `ocr:` 下单独写 `crop_bottom: 0.95`，并按需删掉缓存 `E{NN}.ocr.srt`：它的复用只看视频 mtime，不看 OCR 配置。

## 已知边界

- 15:47–15:50 的 `高校の成積` 仍可能被认出：它是**画面内的教材文字**，不属于底部青色日文字幕，实际位置在中文对白字幕**上方**，所以仅用下沿过滤无法去掉。简单抬高 `crop_top` 会影响中文识别，不应照此改动；这类画面文字需要另行识别/筛除策略或人工校正。
- 这不是语言翻译问题：日文含汉字，单纯靠“含 CJK”、语言检测或 OpenCC 无法可靠排除。`crop_bottom` 要针对具体片源抽样确认；全片其它杂字及 OCR 错字仍可能需要人工校对。
